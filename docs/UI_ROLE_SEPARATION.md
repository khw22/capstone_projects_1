# UI 역할 분리 문서

본 프로젝트는 **두 개의 분리된 UI 개념**을 가집니다.
이 문서는 어떤 UI가 어디에 속하는지, 그리고 왜 그렇게 분리해야 하는지를 정의합니다.

> 핵심 원칙
> - 라즈베리파이 = 엣지 디바이스 + 매우 작은 디버그 UI
> - 중앙 서버 = 학습/저장/배포 + 메인 대시보드 UI
> - 두 UI는 절대 섞지 않습니다.

---

## 1. 라즈베리파이 / Debian 엣지 측

### 역할
- USB CCTV 입력 수집
- 초기 설치 및 설정
- OCR ROI 좌표 설정 (온도/습도 영역)
- 학습용 영상/프레임 데이터 서버로 업로드
- 서버에서 학습/최적화된 모델 또는 룰셋 수신
- 약 3 ~ 5 FPS 수준의 **경량 로컬 추론** 수행
- 오염도 점수 계산
- ROI가 설정된 경우 OCR로 온/습도 값 읽기
- 추론 결과를 서버로 전송
- **최소한의 로컬 디버그 UI만 제공**

### UI
- 위치: `edge-device/local_debug_ui/`
- 성격: 디버그 전용, 단일 디바이스 한정
- 기능 제한:
  - 지도 / 다중 CCTV 관리 / 장기 통계 / 보고서 / 운영자 메인 대시보드 기능 **포함하지 않음**

> Debian VM 환경은 라즈베리파이 4 Model B 의 **개발용 대체 환경**입니다.
> 실제 배포 타겟은 라즈베리파이이며, Debian VM은 동일한 디버그 UI/엣지 코드를 그대로 사용합니다.

---

## 2. 중앙 서버 측

### 역할
- 엣지 디바이스에서 보낸 학습용 영상/프레임 수신
- YOLO 학습 또는 파인튜닝 수행
- 모델 최적화/내보내기
- 추후 모델/룰셋 다운로드 엔드포인트 제공
- 라즈베리파이가 보낸 추론 결과 수신
- 결과 저장/조회
- **메인 운영자용 대시보드 UI 제공**

### UI
- 위치: `server/static_dashboard/`
- 성격: 다중 디바이스 통합 모니터링, 운영자/관리자 사용
- 포함 항목 (현재는 placeholder):
  - 실시간 CCTV 상태
  - 오염도 현황
  - 온습도 정보
  - 이벤트 기록
  - 설정 (서버 상태, 모델 버전 등)

## 3. 메인 대시보드와 로컬 디버그 UI의 차이

| 항목 | 라즈베리파이 로컬 디버그 UI | 중앙 서버 대시보드 UI |
| --- | --- | --- |
| 위치 | `edge-device/local_debug_ui/` | `server/static_dashboard/` |
| 동작 환경 | 라즈베리파이 / Debian VM | 외부 중앙 서버 |
| 사용자 | 설치자/디버거 | 운영자/관리자 |
| 다루는 디바이스 수 | 1대 (자기 자신) | 다수 |
| 지도 | 없음 | 추후 가능 |
| 통계/보고서 | 없음 | 가능 |
| 목적 | 설치 직후 점검, 현장 디버깅 | 상시 모니터링 |
| 의존성 | 없음 (정적 파일) | 없음 (정적 프로토타입 단계) |

---

## 4. 왜 이렇게 분리하는가

- **자원 제약**: 라즈베리파이는 추론과 OCR을 동시에 돌리는 엣지 장치이므로,
  무거운 대시보드 UI를 띄울 여력이 없습니다.
- **역할 명확성**: 디버그/현장 점검과 운영 모니터링은 사용자도 다르고
  필요한 정보의 단위도 다릅니다 (1대 vs N대).
- **확장성**: 디바이스가 늘어나도 메인 대시보드는 서버에서 한 곳으로 통합됩니다.
- **혼란 방지**: 라즈베리파이에 운영자용 메인 대시보드를 두면, 현장 사용자가
  "이 화면이 시스템 전체를 보는 화면"이라고 오해할 수 있습니다.

## 5. 현재 단계에서 구현하지 않는 것

이번 단계는 **UI 역할 분리** 와 **두 UI 프로토타입** 까지만 다룹니다.
다음은 아직 구현하지 않습니다.

- 전체 AI 추론 시스템
- 백엔드 API 전체
- YOLO 학습 파이프라인
- 실제 OCR 파이프라인
- 모델 다운로드/배포 엔드포인트
